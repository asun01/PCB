## Hard gates for every 100-stage acceptance unit

1. Real executable code or a genuinely executable integration artifact.
2. At least one meaningful invalid-state path.
3. Real cross-module handoff; DTO-only work does not qualify.
4. Smoke registered in its owning Smoke program.
5. Exactly 10 `for` loop groups and 10 meaningful `Check(...)` call sites.
6. Explicit `round == 100`.
7. Balanced `{}`, `()`, `[]`.
8. No TODO / NotImplementedException.
9. No tautological assertion.
10. Static audit and 100-stage ledger.
11. Every 500-stage cell gets an integration checkpoint.
12. No build/test/CI success is claimed without authoritative workflow evidence.

## Architecture constraints

- Production remains UI/vendor neutral.
- Evidence remains opaque and does not own Quality or storage.
- Quality does not own Evidence storage.
- Release does not own physical persistence.
- Simulation never masquerades as Production.
- Render is not a Production dependency.
- HALCON, DevExpress, and hardware behavior are introduced only when authoritative project dependencies/contracts exist.
